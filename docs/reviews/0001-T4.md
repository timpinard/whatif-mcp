Decisions taken:
- Each account rule lives once in `core/rules.py` as `check_account(account)`, raising
  `RuleError(WhatIfError)` (new, in `core/errors.py`; Task 0001-T6 can add `check_flow` beside
  it). Rules: a liability balance is never negative; growth_rate greater than -1 and at most 1;
  volatility 0 to 1. Messages name the field and give a hint ("0.07 means 7%").
- `set_account` calls it on the resulting account, so a `kind` change is validated as a new
  account (R2). The store loader calls it in `_account_from_document`; a breaking file account
  is a shape error naming the path, the account and the field (R1 as amended).
- Editing operations are pure functions in `server/operations/`: `accounts.py`
  (`set_account(model, arguments, today) -> AccountEdit`, `remove_account(model, arguments)
  -> AccountRemoval`), `names.py` (trim, case-insensitive exact match, `UnknownNameError`
  listing the names; for Task 0001-T5 and T6), `arguments.py` (`ArgumentError`; typed readers;
  a JSON boolean is not a number; non-finite and overflowing numbers refused).
- `server/tools/accounts.py` is the tool group (load, operate, save, shape); `app.py` adds one
  entry. `previous` holds the earlier values of the shaped fields that differ after the update.
- Write failures: `server/tools/writing.py` `write_model_file` maps the `OSError` from
  `save_model` to a `ModelFileError` naming the path; `save_model` still raises `OSError`
  (AC3). Task 0001-T5 and T6 write tools should use it.

Tests outside the AC naming (owner ruling, conventions.md): `test_R1_load_refuses_account_breaking_an_R2_rule`
(S2), `test_R1_failed_write_is_a_tool_error_naming_the_path`, `test_R2_kind_change_validates_the_resulting_account`,
`test_R16_boolean_is_not_a_number` (S3). `test_AC6_set_account_allows_rate_bounds` checks the
"Allowed" ranges AC6 states.

Seam questions and flags for the owner (not reconciled):
1. `previous` keeps only fields whose value changed. A field given with its current value is
   left out; balance_as_of appears when a balance is given on a later day. R2 / Interfaces say
   "the changed fields' earlier values"; read literally.
2. `new_name` on an account that does not exist is refused (error naming new_name). The spec
   does not say.
3. JSON null for a `set_account` argument is refused as the wrong type. R4 defines null only for
   `set_flow` fields.
4. Unknown arguments (for example "balnce") are ignored: the input schema says
   `additionalProperties: false`, but the SDK does not validate (Task 0001-T1). R16 "every invalid
   input" could cover it; not done, no AC.
5. A new account's name is stored trimmed ("  Savings " -> "Savings"). R8 "the stored spelling
   is kept" is read as the trimmed spelling.
6. A blank name is refused by the tools (name handling, R8), not by `check_account`; a file
   account with a blank name still loads. R1 as amended names R2 and R4 rules only.
