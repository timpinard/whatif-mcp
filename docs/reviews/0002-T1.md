### Decisions
- Interfaces. `core/comparison.py`: `compare(baseline, hypothetical, account_matches,
  flow_matches) -> Comparison`, all values unrounded, plus `difference_values(comparison)` for the
  reportable check. `EntryMatch(baseline_name, hypothetical_name)` is the matching input; its
  `name` is the hypothetical name, else the baseline name (R7). `server/operations/what_if.py`:
  `apply_changes(model, changes, today) -> AppliedChanges(model, descriptions, account_matches,
  flow_matches)`, separate from comparing (for Spec 0003). T1 builds the matches with
  `match_by_name` after applying: baseline order, then hypothetical-only names in hypothetical
  order. T3 replaces it with the tracked map.
- One-sided accounts: R3 says the missing side's block is null but does not say what
  `end_difference` and `growth_difference` are then. The missing side counts as 0 (New fund
  shows +1000.00 end_difference), the same way R3 treats a missing flow total as 0.00. No AC checks
  this. Flagged for the spec reviewer and the owner.
- Flow filter "differs to the cent": compares the rounded totals (Plan 0002, Risks). The
  difference shown is from the unrounded totals.
- `applied` wording (amended R3): an update is `set_flow 'Salary': amount 4000.00 -> 3600.00`. It
  lists every shaped field that differs, so a balance change also shows `balance_as_of`. A rename
  shows `name "Car loan" -> "Auto loan"`. An identical change is `... : no change`. A create is
  `set_flow 'Gym': created with from "Checking", amount 50.00, frequency "monthly", start_date
  "2026-11-01"`, which lists the given fields, with values as stored. A remove is
  `remove_flow 'Car payment'`. Money is shown with two decimals. Other values are shown as JSON.
- Reportable check (amended R2): both projections are checked (after deflation when
  `in_todays_money`), then every difference. `check_reportable` in `operations/projection.py` now
  delegates to a new `check_reportable_values(values)`, so the error text is the one `project`
  gives. `project`'s behavior is unchanged.
- The horizon/today/granularity block of `project`'s result moved to `shaping.shape_horizon` and
  is shared by both tools. `project`'s output is unchanged, and the Spec 0001 tests pass.
- `what_if` loads the model once (`load_model` only). It checks the baseline has accounts, as
  `project` does, before applying changes. It writes nothing.
- Left to T2, per the task notes: change-list validation (non-object change, missing or unknown
  `op`, unknown keys inside a change), the "change N:" prefix, and the hypothetical-has-no-accounts
  error. Until T2 lands, an unknown op is applied as `remove_flow`, and a missing `op` is an
  internal error.
- Size: about 402 lines added under `src/` (337 non-blank, 15 removed). That is at the ~400 split
  line. AC10 is about 10 of those lines (deflate both sides, the `values` block), so it stayed in
  T1. Moving it to a T1b would not bring the task meaningfully under the line.

    granularity dropped before parsing (so the monthly limit was not applied). AC10 failed each
