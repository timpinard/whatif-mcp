### Decisions
- R7 matching is tracked while changes are applied, in `server/operations/what_if.py`, by a
  private `_EntryTracker` per kind (accounts, flows), as the task notes and Plan 0002 say: each
  entry holds its baseline name (or none) and its current hypothetical name (or none once
  removed). `match_by_name` (T1's interim, finding K4) is deleted; `apply_changes` keeps its
  signature and `AppliedChanges` its fields, so `core/comparison.py` and `tools/what_if.py` are
  unchanged.
- The tracker is updated only after the editing operation succeeds, from what the operation
  reports (`previous` and the new name for a set; the removed entry's name for a remove), so the
  names are the stored ones, never the caller's spelling ("auto loan" in AC11 follows "Auto loan").
- A set with no previous entry is a create: it resumes the entry removed earlier under that name,
  else it appends a new entry (creation order, after the baseline entries). Removed names are
  compared ignoring case, as names are everywhere (Spec 0001); the casefold is repeated here
  rather than importing `names._matching_key`, which is private.
- If two entries were removed under the same name (remove X, rename A onto X, remove X), a later
  create of X resumes the most recently removed one. The spec does not say which; no AC covers it.
- An entry created and then removed in the same list has neither side and is dropped (it would
  otherwise be an `EntryMatch` with no name).
- Size: 64 lines added and 21 removed under `src/` (54 non-blank added), all in
  `server/operations/what_if.py`.
- Not done here, by instruction of the caller: Spec 0002 Status and the metrics row (task notes
  give them to T3; the build skill does them).
