## Implementer notes
Covers AC3 (S2, `tests/test_0001_store.py`), AC11 and AC26 (S3, `tests/test_0001_show_model.py`).
Each test was seen red first: AC3 and AC11 on the missing store module and the missing
`show_model` tool; AC26 against a half-even `round(value, 2)` (0.12 != 0.13) before the half-up
helper was restored. About 370 non-test lines, 205 of them `store.py` (shape checks).

Decisions taken:
- `whatif_mcp.store` is one module: `resolve_model_path()` (env var, else `~/.whatif/model.json`,
  read per call), `load_model(path)`, `save_model(path, model)`, `ModelFileError(WhatIfError)`.
  A missing file loads as `Model()` and is not created.
- Load errors name the path and "is not valid JSON", "has version N" or "does not match the
  version 1 shape: <problem>". The shape check covers every key of the Spec 0001 file example;
  a JSON boolean is not a number (as in Task 0001-T4 notes). No test here: AC2 belongs to T5.
  Checked by hand through the in-process client: all three reach the client with `isError: true`.
- Save: `mkdir(parents=True)`, `tempfile.mkstemp` in the target directory, write, chmod 0600,
  `os.replace`. On any failure the temp file is removed and the original exception re-raised
  (an `OSError`, not a `WhatIfError`); mapping write failures to a tool message is left to the
  first write tool (T4). Key order follows the spec example; floats are written as floats.
- Tool registry: `server/registry.py` holds `ToolCall` (arguments, today), `RegisteredTool`
  (MCP `Tool` definition + handler), dispatch and the `WhatIfError` -> `isError: true` mapping.
  `server/tools/read.py` exports `TOOLS`; `app.py` only concatenates group tuples and calls
  `create_registry_server`. T4 to T6 add `tools/accounts.py`, `tools/flows.py`,
  `tools/project.py` and one line each in `app.py`. "Today" is read once per call in dispatch.
  An unknown tool name is a tool error listing the tools.
- Success results carry the dict as `structured_content` and as JSON text content.
- `server/shaping.py`: `round_money` (Decimal from `repr(value)`, ROUND_HALF_UP to 0.01),
  `shape_account`, `shape_flow` for reuse by T4 and T6 results.
- Fixtures added to `tests/conftest.py` as separate functions: `write_model_file` (writes a
  `Model` through the store to the test's model path), `model_w_file_form` (Model W as a core
  `Model`, balance_as_of today), `model_w_file` (Model W written to the file).

Seam questions and flags for the owner:
1. Net worth today is computed in `tools/read.py` (assets minus liabilities over stored
   balances), not in core, so as not to touch core while T2 builds its projection. If T2 adds a
   core net-worth function, `show_model` should use it after both merge.
2. `model_w_file_form` overlaps T2's Model W core builder; one can replace the other at rebase.
3. "Half up" on negative ties: `ROUND_HALF_UP` rounds away from zero (-0.125 -> -0.13). The
   spec does not say; no AC observes it.
4. Half up is applied to `repr(value)` (the shortest decimal that round-trips), so 1.005 shows
   1.01 although its binary value is just below 1.005. Read as "half up on the unrounded value".

Rework (regeneration 1): rebased on main after Task 0001-T2; `model_w_file_form` is gone and
`model_w_file` writes T2's `model_w`. Load now refuses, as R1 shape errors naming the path,
duplicate account or flow names (trimmed, case-insensitive per R8) and a flow `from`, `to` or
`rate_of` that is not the exact stored name of an account; `version` must be the JSON integer 1
(`true` and `1.0` are refused, a missing key reads "has no version"); NaN, Infinity and overflow
to infinity are refused per field. The temp file is flushed and fsynced before `os.replace`. The
shape message uses `FILE_VERSION`. Tests, each seen red first, are at S2 in
`tests/test_0001_store.py` and named `test_R1_*`: no Spec 0001 AC covers these loads (AC2 is
Task 0001-T5's and covers only invalid JSON and version 2), so they sit outside the
`test_<AC-id>_` convention. The fsync is not observed by any seam; checked by review. Flag: a
flow with neither `amount` nor `rate`, or `rate` without `rate_of`, still loads and would trip
the assertion in `core/projection.py` when projected; that consistency check was not in the
rework list.

Rework (regeneration 2): an integer too large for a float is now a shape error ("is too large
to be a number") instead of an `OverflowError`; a flow with neither `amount` nor `rate`, or with
`rate` but no `rate_of`, is a shape error naming the flow; the `_check_unique` parameter is
`entity`; the version tests build their input from a dict. New S2 tests in
`tests/test_0001_store.py`: `test_R1_load_refuses_integer_too_large_for_a_float` and
`test_R1_load_refuses_flow_without_amount_or_complete_rate`, both seen red first, and a
" Checking " case in the duplicate-name test. The trim was already implemented, so that case
passed at once; it was seen red by removing `.strip()` for one run. Non-test lines are now 420.

AC coverage: AC3 (S2) patches `os.replace`, asserts the raise and identical bytes; AC11 (S3) all
literal expectations incl. net_worth_today -5000.00, field sets, flow order; AC26 (S3) 0.125 is
binary-exact, so half-up vs half-even is distinguished for balance and net_worth_today. None
stubbed or tautological.

Missing or partial:
1. Medium: load does no reference checks. R1: "A file that is valid JSON with version 1 but
   does not match the version 1 shape is treated the same as invalid JSON." A flow whose
   `from`/`to`/`rate_of` names a missing account, or duplicate names, loads; a hand-edited file
   can reach `project` (Task 0001-T5) and crash with a non-`WhatIfError`.
2. Low: R1 / ADR 0003 "Every write replaces the file atomically": no fsync of the temp file
   before `os.replace`; a power loss can leave an empty file on some filesystems. No AC observes.
3. Low: a shape error says "does not match the version 1 shape", not "not valid JSON". Follows
   the task notes ("or the shape problem"); "treated the same as invalid JSON" could be read as
   the same text. Owner to confirm.

Not in the spec:
4. `UnknownToolError` listing the tools (`registry.py`). Small, harmless.
5. Success results also carry the JSON as text content. Reasonable for MCP clients.

Present but looks wrong:
6. Low: `load_model` accepts `"version": true` and `1.0` (`True == 1`). R1: "The file carries
   `"version": 1`". A missing version reads "has version None".
7. Low: NaN and Infinity in numbers load as valid (Python's JSON parser accepts them).
8. Note (implementer flag 1): net worth computed in `server/tools/read.py` repeats R13's
   "assets minus liabilities"; reconcile with the Task 0001-T2 core after both merge.
9. Note (implementer flag 3): -0.125 -> -0.13 (away from zero) is not settled by "Money in
   results is rounded to cents, half up". Owner to decide.

Other: ASCII clean, no out-of-scope edits, `today` read once per call in dispatch.
