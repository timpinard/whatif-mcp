## Implementer notes
Decisions taken:
- `main()` in `server/stdio.py` calls `logging.basicConfig(level=logging.INFO, stream=sys.stderr)`
  before serving. No setting changes the level (R19). The server adds no log lines of its own:
  no requirement asks for one, so INFO stderr is empty in practice. No `print` in src.
- `tests/test_0001_stdio.py` runs the installed console script (`whatif-mcp`, next to the test
  interpreter in the venv) as a subprocess, speaks newline-delimited JSON-RPC: initialize, the
  initialized notification, Model W through `set_account` and `set_flow`, `show_model`,
  `project`, then one rejected call, `set_flow(name="Salry", amount=4100)` (unknown flow; the
  error lists "Salary, Car payment"). Every stdout line read during the session and after
  stdin closes is parsed as JSON with `"jsonrpc": "2.0"`; stderr is checked for none of
  "Checking", "Salary", "Car loan", "4000". The `isError` checks on each call only confirm the
  session did what the AC's Given needs; the AC's assertions are the stdout and stderr ones.
- The model path comes from the existing `model_path` fixture (`WHATIF_MODEL_PATH` in a temp
  dir), inherited by the subprocess environment.

SDK loggers (mcp 2.3.0, from source and a probe run):
- The modules on our path (`server/lowlevel`, `server/stdio.py`, `server/runner.py`,
  `shared/jsonrpc_dispatcher.py`, `shared/dispatcher.py`) have no `logger.info` call. Their
  WARNING and ERROR calls name a JSON-RPC method or request id ("handler for %r raised", "%s
  gave up: transport write blocked"), plus a traceback for `logger.exception`; none formats tool
  arguments. `shared/tool_name_validation.py` warns with a tool name (ours are fixed names, not
  user data). INFO calls exist only in modules we do not load: streamable HTTP, the high-level
  `mcpserver`, the CLI and the client.
- Probe: the AC25 session through the console entry point wrote 0 bytes to stderr. The same
  session at DEBUG wrote three lines, none with user data: "Using selector: KqueueSelector",
  "Initializing server 'whatif-mcp'", "no handler for notification notifications/initialized".
- The `print` in `shared/metadata_utils.py` is inside a docstring example, not code.

Red first:

  nothing reached stderr, and stdout was already MCP only (Task 0001-T1's entry point). It still
  passed after logging was set to INFO. To show the test can fail, two temporary mutations of

Seam questions and flags (not reconciled):

  (Plan 0001 S4). The marker and convention text were left as they are.
- The test reads stdout with a blocking `readline`; if the server ever stopped answering
  without closing stdout, the test would hang rather than fail (no pytest timeout dependency;
  one would need an ADR). A crashed server closes stdout and fails the test.
- Nothing found that disagrees with Spec 0001.
