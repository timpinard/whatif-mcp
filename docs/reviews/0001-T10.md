Decisions taken:
1. The cents helper moved from `server/shaping.py` to a new `core/money.py`, because core's
   reaches_zero now needs it and core does not import server. `shaping.py`, `tools/read.py` and
   `tools/project.py` import it from core; no re-export left behind.
2. `round_money` returns 0.0 for any value that rounds to zero, so no tool result (project,
   show_model, set_account, set_flow) can carry -0.0.
3. reaches_zero uses `rounds_to_zero_or_below(value)`, i.e. `value < 0.005`, for both the
   before and after balance. My first cut called `round_money` there; that made the existing
   `test_AC27_projection_too_large_to_report_names_horizon_years` fail with
   `decimal.InvalidOperation` (a 7.2e26 balance exceeds Decimal's 28-digit precision, and core
   runs before the R14 check). The threshold gives the same answer as half up on the float's
   repr (repr(0.005) is "0.005", which rounds to 0.01) and avoids Decimal per event per account.
4. The 100-year rule sits in `check_flow`, which now takes `today`; `set_flow` and the loader
   both call it. `load_model(path, today)` gains a `today` parameter: every tool passes
   `call.today`, and the store unit tests take the fixed `today` fixture.
5. The earliest start is `horizon_end_date(today, -100)` (validation imports it from
   projection; no cycle), so today = 29 Feb in a year whose 100-years-earlier year has no 29 Feb
   (2000, 2400) clamps to 28 Feb, as R13 does for the horizon.

Seam questions: none. The loader signature change follows from the task note ("set_flow and the
loader share it"), since the loader had no today.

Flags for the owner (not reconciled):
- A model file that is valid today can become unreadable later: a flow starting exactly 100
  years back loads today and is a shape error tomorrow, and then every tool refuses the file,
  including `remove_flow`, so only a hand edit repairs it. This follows R1 via R4 as written.
- The 100-year rule also applies on update of an existing flow whose start_date is not given
  (R4: the resulting flow satisfies every create rule); in practice the loader refuses such a
  file first.
