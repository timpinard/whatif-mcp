### Decisions
- Change-list shape (`changes` missing, not a list, or empty) is checked in the handler
  (`tools/what_if.py`, `_changes`) after the projection options and before the model is loaded:
  `changes must be a non-empty list of changes, not [].` A missing `changes` gets the same
  message (`not None`); it was an internal error (KeyError) before.
- Each change is validated inside `apply_changes`, in order, so a malformed change 3 is reported
  only after changes 1 and 2 applied cleanly. Every `WhatIfError` raised while validating or
  applying change N is re-raised as `ChangeError("change N: <original message>")`, so the text
  after the prefix is exactly what the tool reports (AC7, test_R6_unknown_key...).
- Messages: non-object `change 2: must be an object with op and that tool's arguments, not
  'Salary'.`; missing op `change 2: op is required, one of set_account, remove_account, set_flow,
  remove_flow.`; non-text or unknown op `change 1: op must be one of set_account, remove_account,
  set_flow, remove_flow, not 'rename'.` Non-text and unknown share one message.
- Unknown keys: the registry's `_check_argument_names` is made public as `check_argument_names`
  (rename only, behavior unchanged) and called with the op's tool definition. `apply_changes`
  takes a new `op_definitions: Mapping[str, types.Tool]` argument; the handler builds it from
  `accounts.TOOLS` and `flows.TOOLS`. So `tools/what_if.py` now imports `tools/accounts` and
  `tools/flows` (one tool module depending on others, the concern of T1's J5). The definitions
  live only there; passing them in keeps `operations/` from importing `tools/`. Spec 0003 will
  need to pass the same mapping.
- The interim fall-through of T1 (S5, J1) is gone: `_op` admits only the four ops, so the final
  `remove_flow` branch is reached only for `remove_flow`. A missing op is a tool error.
- Hypothetical with no accounts: checked in the handler right after applying, before projecting,
  with `EmptyModelError("The hypothetical model has no accounts to project: the changes remove
  every account.")`. It names no position: it is about the list, not one change.
- Baseline with no accounts: `check_has_accounts(model)` stays before `apply_changes`, so an empty
  model gives `project`'s error even when change 1 would fail (test_R6_baseline...).
- `isinstance(op, str)` in `_op` is redundant at runtime (`op not in OPS` already rejects every
  non-string) but mypy needs it to narrow to `str`. Removing it was tried and failed the typecheck,
  so it cannot be seen red by a test.
- The robustness test imports `HOSTILE_VALUES`, `build_arguments` and `find_protocol_error` from
  `tests/test_0001_robustness.py` rather than copying them. Failure lines are cut to 300 chars
  (the shared `describe_call` does not shorten values nested in the change list). 400 calls, seed
  20261008, model reset every 40 calls to Model W or (1 in 5) an empty model.
- Size: 57 lines added and 8 removed under `src/` against b421118 (about 50 non-test lines of
  new logic; 2 of the changed lines are the registry rename).

### Rework 1
These are fixes for the owner's list: Q1, Q2 and Q3 as one change, then Q4, Q5, Q6, Q8 and Q10.
The waived findings were left alone.
- Q1, Q2, Q3: `operations/what_if.py` has a typed `Change(op: str, arguments: Mapping[str, Any])`.
  `apply_changes(model, changes: Sequence[Change], today)` no longer takes `op_definitions`, and
  `operations/` no longer imports the registry or `mcp.types`. The handler now checks the shape
  of every change, in order and before any change is applied (`tools/what_if.py`,
  `_parse_changes`, `_parse_change`, `_parse_op`). It checks for an object, `op` present and one
  of the four, and unknown keys (`check_argument_names` against `OP_DEFINITIONS[op]`). Then it
  builds the `Change`. A shape error is raised as "change N: ..." through
  `operations.what_if.change_error(position, error)`. `apply_changes` uses the same helper for
  value errors, so the prefix is built in one place.
  Accepted consequence: a malformed later change is reported before an earlier change's value
  error. No existing test observes that order, so no test was changed for it.
- Q4: `OPS_LISTED = ", ".join(OPS)` is a constant in `operations/what_if.py` and is used by both
  op messages.
- Q5: `check_hypothetical_has_accounts(model)` is a sibling of `check_has_accounts` in
  `operations/projection.py`. The message is unchanged.
- Q6: `_changes` is renamed `_parse_changes`.
- Q8: the shared robustness pieces moved from `tests/test_0001_robustness.py` to
  `tests/helpers.py`: the value pools, `TOOL_POOLS`, `ALWAYS_BUILT_ARGUMENTS`, `build_arguments`,
  `describe`, `describe_call` and `find_protocol_error`. They were moved unchanged.
  test_R16_no_tool_returns_an_internal_error keeps its seed, call count and reset interval, and
  imports what it needs from `helpers`.
- Q10: `OPS_LISTED` and `REMOVE_EVERYTHING` in `tests/test_0002_refusals.py` now sit with the
  other constants at the top.

The checks moved, so each one was broken again at its new place in `tools/what_if.py` (and the
