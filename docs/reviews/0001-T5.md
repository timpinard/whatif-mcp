## Implementer notes
Covers AC1, AC2, AC22, AC23, AC24 (S3, `tests/test_0001_project_tool.py`). 262 non-test
lines added, 2 removed (`git diff --numstat main...HEAD -- src`, blank lines included).

Red first: AC22 defaults failed on "There is no tool named project"; the AC22 argument cases
failed on the registry's unknown-argument check (horizon_years, granularity) and on the empty
model; the AC23 today's-money test failed on the unknown argument `in_todays_money`; the AC23
`set_inflation_rate` tests failed on "There is no tool named set_inflation_rate". AC1, AC2 and
AC24 were written after the `project` tool existed, so they were seen red by running them
with `app.py` as on main (project tools not registered): each failed on "There is no tool named
project". `test_R15_flow_totals_deflate_at_the_horizon_end` passed on its first run (the
deflation already existed); it pins the R15 date rule for flow totals and summary values,
which AC23 does not observe (a flow at 2026-11-01 deflated at the horizon end gives 97.09, at
its own date 99.79).

Decisions taken:
- Deflation is in core, new module `core/todays_money.py`: `in_todays_money(projection,
  inflation_rate) -> Projection`, unrounded, `value / (1 + rate) ^ (max(0, days) / 365.25)`.
  Rows use their end_date; start_balance uses today (factor 1); end_balance, growth_total and
  flow totals use the horizon end; reaches_zero is a date and is untouched. A separate module
  keeps clear of `core/projection.py`, which Task 0001-T6 edits (the `assert`).
- `server/tools/project.py` is the "project" tool group and holds `project` and
  `set_inflation_rate` (Plan 0001 names four groups; inflation is the rate `project` uses).
  `app.py` adds one entry; Task 0001-T6 adds `flows` to the same line, a one-line merge.
- Horizon shaping per the Task 0001-T2 spec review: `years` is the argument, `from`/`to` are the
  first and last row labels, `end_date` is `Projection.horizon_end`.
- `horizon_years`: read with the shared number reader (booleans and non-finite refused), then
  whole and 1 to 50; 5.0 accepted and reported as 5. The schema says `integer` as a hint to the
  client; the SDK does not validate it (Task 0001-T1). `granularity` uses `optional_choice`, so
  the error lists "monthly, quarterly, annual". Monthly over 10 years names granularity, "10
  years" and suggests quarterly or annual. Arguments are checked before the file is loaded.
- The empty-model error is raised after a successful load, so a corrupt file still reports the
  file problem (AC2).
- `set_inflation_rate`: pure operation `server/operations/inflation.py` (Spec 0002 can apply it
  to an in-memory model), the range rule once in core as `check_inflation_rate` (greater than -1,
  less than 1, hint "0.03 means 3%"), prefixed with the argument name like `finite_number`.
  Writes through `server/tools/writing.py`. `previous` is the model value before the change.
- `server/operations/arguments.py` gains `required_number` and `optional_boolean` (a non-boolean
  `in_todays_money` is refused, not coerced).
- Result key order follows the spec example: `values` (and `inflation_rate` for todays_money)
  right after `granularity`.

Seam questions and flags for the owner (not reconciled):
1. The store loader does not check `inflation_rate` against the set_inflation_rate range. R1 as
   amended names only R2 and R4 rules for file accounts and flows, so a hand-edited file with
   `inflation_rate` -1 loads, and `project` with `in_todays_money` then fails inside core with
   an unhandled `ZeroDivisionError` (below -1: `ValueError`, math domain), not a `WhatIfError`
   naming the path. Nominal projection is unaffected. Calling `check_inflation_rate` from the
   loader is one line, but it would be a spec change to R1.
2. Tests use local `succeed`/`fail` helpers, duplicating those in `tests/test_0001_accounts.py`
   (the pattern `test_0001_show_model.py` also follows). Moving them to `conftest.py` would
   touch a file Task 0001-T6 may also edit; left for a later cleanup.
