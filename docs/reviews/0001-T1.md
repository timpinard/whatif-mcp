## SDK verification (Plan 0001, Risks; Tasks 0001, T1 notes)
Installed: `mcp` 2.3.0 (resolved by `uv add mcp`, locked in `uv.lock`). Checked with a throwaway
probe: a low-level `Server` with one tool whose input schema declares `from` (string or null)
and a required number `balance`, with `additionalProperties: false`.

- In-process session API: `mcp.Client(server)` used as an async context manager connects to a
  `mcp.server.lowlevel.Server` in-process (in-memory transport) and initializes. It negotiates
  protocol version 2026-07-28. `ping` is removed in that version (the SDK raises "Method not
  found"), so the smoke test checks `server_info` instead.
- An argument named `from`: reaches the `on_call_tool` handler unchanged in
  `params.arguments["from"]`. No renaming or keyword mapping is involved.
- Omitted vs null: an omitted argument is absent from `params.arguments`; an argument passed as
  JSON null is present with value `None`. The two are distinguishable.
- Input-schema validation: none, on either side. The server calls the handler with
  `balance="lots"`, with a missing required argument, and with an undeclared extra argument;
  this holds also after the client has called `tools/list`. The server's
  `get_tool_input_schema` hook is used only for HTTP `Mcp-Param` header checks, not for stdio.
  So every R16 message comes from our own validation, and schemas can be exact without
  hiding our messages.
- Low-level `Server` takes handlers as constructor arguments (`on_list_tools`,
  `on_call_tool`), not decorators. T1 registers none.

## Decisions within the task
- Core types: `Model`, `Account`, `Flow` (frozen dataclasses), `AccountKind`, `Frequency`
  (StrEnum with the spec's wire values), `WhatIfError`. The flow sides are `from_account` and
  `to_account` in Python, since `from` is a keyword.
- `occurrence_dates(start, frequency, end)` yields dates lazily, `end` inclusive and `None`
  meaning unbounded. Filtering to "strictly after today, on or before the horizon end" is left
  to the projection (T2).
- `create_server(today)` accepts the today callable but does not use it yet; tools that read
  it arrive in T3 onward.
